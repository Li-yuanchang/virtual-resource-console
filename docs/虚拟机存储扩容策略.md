# 虚拟机存储扩容策略

## 目标

VRC 将“虚拟硬件扩容”和“Guest 文件系统生效”作为同一个业务操作编排，但保持实现边界独立。支持 XenServer、Proxmox VE、VMware 的原盘扩容与新增磁盘，并在 Linux Guest 内自动完成分区、LVM、文件系统和挂载处理。

## 分层职责

- Provider 层：只调用虚拟化平台 API 修改 CPU、内存和虚拟磁盘，不执行 Guest 命令。
- GuestStorageService：通过 SSH 只读探测块设备、分区、挂载目录和空目录，并执行受控的存储命令。
- API 编排层：按“预检 -> 平台变更 -> Guest 生效 -> 回读”执行，统一处理三平台差异和部分完成状态。
- Web 组件：只展示 API 返回的真实目录和磁盘映射，不推测 Guest 结构，不拼接 Shell 命令。

虚拟硬件扩容与 Guest 自动生效是两层能力：XenServer、Proxmox VE、VMware 的 CPU、内存和虚拟磁盘变更只依赖平台连接，不要求 Guest 登录。分区、LVM、文件系统、格式化和挂载属于 Guest 内部操作，需要可用的 SSH 或 Guest Agent 执行通道。VRC 的“磁盘扩容”入口以目录容量最终生效为完成口径；执行通道不可用时禁止只提交虚拟磁盘变更，避免平台容量增大但系统目录不变。

## 原盘扩容

1. 读取平台虚拟磁盘清单。
2. 通过 Guest `lsblk`、`df` 读取磁盘、分区、LVM 和真实挂载目录。
3. 按 XenServer 设备号或磁盘容量、顺序映射平台磁盘与 Guest 磁盘。
4. 过滤 `/boot`、`/boot/efi` 等不允许作为普通数据扩容目标的目录。
5. 执行前验证目标目录、磁盘映射以及 `growpart/parted/sfdisk`、LVM、XFS/ext 工具。
6. Provider 扩大虚拟磁盘；不支持在线扩容时按原策略正常关机并自动启动。
7. Guest 回读新容量后扩展末尾分区；LVM 使用本次增量扩展目标 LV，不占用与本次操作无关的全部 VG 空间。
8. XFS 使用 `xfs_growfs`，ext2/3/4 使用 `resize2fs`，最后回读挂载目录容量。

CentOS 7 兼容顺序为：优先 `growpart`；其次使用支持 `resizepart` 的新版 `parted`；旧版 DOS 分区表使用 `sfdisk -N` 只重写目标末尾分区。`sfdisk` 执行前保存分区表备份，并在命令因内核占用返回非零时回读磁盘表确认是否已经写入。若磁盘表已更新但内核仍是旧容量，VRC 自动正常重启 Guest 一次，等待 SSH 恢复后继续 `pvresize`、`lvextend` 和文件系统扩展。

平台磁盘已经扩大、Guest 尚未生效时，存储探测会根据磁盘末尾空闲、分区与 PV 容量差、VG 空闲容量计算“待分配容量”。用户无需再次增加虚拟磁盘，可直接选择目标目录完成续作。

LVM 设备路径必须使用 `df/findmnt` 返回的稳定挂载源，例如 `/dev/mapper/<vg>-<lv>`。`lsblk` 的 `dm-N` 仅用于识别设备关系，编号会随启动和设备映射变化，也不能作为旧版 `lvextend` 的目标参数。

## 新增磁盘

1. 执行前记录 Guest 当前磁盘清单并校验目标挂载目录。
2. 下拉候选仅包含 `/data`、`/mnt`、`/srv`、`/opt` 中真实存在、未挂载且为空的顶层目录。
3. 允许输入上述根目录下的新路径；路径不存在时由 VRC 创建。
4. Provider 创建并挂载新虚拟盘。
5. Guest 重新扫描 SCSI 设备，以“新增设备 + 容量匹配”唯一识别本次磁盘，禁止格式化已有文件系统的设备。
6. 新盘创建 GPT 分区和 XFS，使用文件系统 UUID 写入 `/etc/fstab` 后挂载。
7. 写入前备份 `fstab`；挂载失败时恢复备份，并返回部分完成状态。
8. 最终必须回读新挂载目录及容量；低于虚拟磁盘目标容量的安全阈值时判定失败。重启验证时，新目录必须依靠 UUID/`fstab` 自动恢复挂载。

## 新建系统磁盘布局

- CentOS 7 无人值守安装禁止继续使用 Anaconda 默认 `autopart --type=lvm`，该策略会保留未分配空间，导致 120 GiB 虚拟盘仍只有约 42 GiB `/home`。
- Kickstart 显式创建 500 MiB `/boot`、50 GiB 根目录、8 GiB swap，并让 `/home` 使用 `--grow` 接收其余容量；小于标准规格的磁盘会动态缩小根目录，但不低于 20 GiB。
- CentOS 7 安装包列表包含 `cloud-utils-growpart`，后续原盘扩容优先使用成熟的 `growpart`。
- 该策略在安装阶段完成，不依赖安装后的 Guest SSH 登录。后续对已安装系统扩容时，虚拟硬件仍由平台完成，分区/LVM/文件系统生效继续走 Guest 执行通道或平台能力降级策略。

## 安全与失败语义

- 所有 Guest 密码字段沿用 RSA-OAEP + AES-GCM 请求加密，不写入日志。
- 默认密码可按运行策略和 VM IP 临时推导；服务端不把密码写入扩容记录。
- 所有会修改平台或 Guest 的动作之前必须完成只读预检。
- 平台变更失败：整体失败，不执行 Guest 命令。
- 平台成功、Guest 失败：返回“虚拟硬件已扩容，但 Guest 自动生效失败”，前端按部分完成展示并刷新平台容量，禁止假报整体成功。
- Guest 预检或认证失败：不重复展示错误；CPU/内存操作仍可执行，磁盘扩容按钮保持禁用并提示等待 Guest 执行通道，不允许降级为虚拟硬件单层成功。
- 磁盘只允许增大，不支持缩小。
- 新盘格式化前必须同时满足：本次新增、容量匹配、无文件系统、未挂载。

## 当前验证

- 单元测试覆盖 CentOS 7 LVM 清单解析、稳定逻辑卷路径、XenServer 磁盘映射、原盘扩容命令和新盘格式化挂载命令。
- XenServer `129.21_test2` 原盘续作实测通过：平台磁盘保持 120 GiB，自动扩大 `/dev/xvda2`，重启后执行 PV/LV/XFS 扩展，`/home` 从约 42 GiB 增至约 62 GiB。
- XenServer `129.21_test2` 新盘实测通过：在线新增 20 GiB `/dev/xvdb`，创建 GPT/XFS，使用 UUID 写入 `fstab` 并挂载 `/data`；正常重启后 `/home` 和 `/data` 均自动恢复，容量回读一致。
- VMware 只读实机验证通过：平台 VMDK 可与 Guest `/dev/sda`、LVM、`/`、`/home` 正确关联。未选择业务测试 VM 执行真实扩盘。
- PVE 平台磁盘解析和 API 命令由自动测试覆盖；当前可见 VM 的 Guest 账号不符合默认口令规则，尚未对真实 VM 执行变更验证。
