# 虚拟机存储扩容策略

## 目标

VRC 将“虚拟硬件扩容”和“虚拟机操作系统文件系统生效”作为同一个业务操作编排，但保持实现边界独立。支持 XenServer、Proxmox VE、VMware 的原盘扩容与新增磁盘，并在 Linux 虚拟机操作系统内自动完成分区、LVM、文件系统和挂载处理。本文中的“虚拟机操作系统”对应代码内部的 Guest 概念，不是指 XenServer、Proxmox VE 或 VMware 平台。

## 需求与完成口径

- 原盘扩容必须以用户选择的现有挂载目录容量实际增加为完成，不得只以 VDI、VMDK 或平台磁盘容量增加作为成功。
- 新增磁盘必须以新磁盘完成识别、分区、格式化、写入 `fstab`、挂载到目标目录并回读容量为完成。
- 虚拟机操作系统执行通道不可用时禁止降级为“只扩虚拟硬件”。CPU、内存仍可独立执行，磁盘扩容必须等待系统内预检通过。
- 前端默认只提交目标 CPU、目标内存、磁盘动作、目标容量和最终生效目录，不提交系统 IP、设备路径、分区路径、文件系统类型或平台执行方式。后端默认执行通道不可用时，允许用户提供系统 Login/Password 和可选 JumpServer 连接；凭据加密传输，仍由后端决定执行策略。
- 后端根据 Provider 类型、VM 电源状态、平台磁盘能力和系统存储清单选择在线或停机、原盘或新盘、平台 API 和系统内容量生效策略。
- XenServer、Proxmox VE、VMware 必须接收同一请求模型并返回同一结果模型；平台差异不得扩散到前端条件分支。

## 分层职责

- Provider 层：只接收后端编排生成的执行请求，调用虚拟化平台 API 修改 CPU、内存和虚拟磁盘，不执行虚拟机操作系统命令。
- GuestStorageService：通过 Provider 选择的系统执行通道只读探测虚拟机操作系统的块设备、分区、挂载目录和空目录，并执行受控的存储命令。Proxmox VE 优先使用已启用的 QEMU Guest Agent；XenServer 默认使用宿主机跳板 SSH；PVE、VMware 可使用 Guest SSH 直连或用户明确配置的 JumpServer。VMware Tools 仅提供监控和电源协助，不等价于 Guest Operations 命令执行。
- API 编排层：解析 VM IP 和系统存储映射，选择 Provider 与系统执行策略，按“预检 -> 平台变更 -> 操作系统生效 -> 回读”执行，统一处理三平台差异和部分完成状态。
- Web 组件：只提交标准化扩容意图并展示 API 返回的真实目录、执行状态和统一结果，不判断平台策略，不推测虚拟机操作系统存储结构，不拼接 Shell 命令。

虚拟硬件扩容与操作系统自动生效是两层能力：XenServer、Proxmox VE、VMware 的 CPU、内存和虚拟磁盘变更只依赖平台连接。分区、LVM、文件系统、格式化和挂载属于虚拟机操作系统内部操作，需要后端建立可用的 SSH、QEMU Guest Agent 或其他系统代理执行通道。PVE 的管理 API 登录与 VM 的系统登录是两套认证：前者用于调用 PVE API，后者只有在没有可用 Guest Agent、且平台策略选择 SSH 时才需要。VRC 的“磁盘扩容”入口以目录容量最终生效为完成口径；后端无法建立执行通道时禁止提交平台磁盘变更，避免平台容量增大但系统目录不变。

## 前后端契约

- 前端磁盘请求包含 `mode`、平台磁盘或存储标识、目标容量，以及 `storageTarget.mountPath`。后端返回 `SYSTEM_AUTHENTICATION_REQUIRED` 或 `SYSTEM_EXECUTION_UNAVAILABLE` 后，可附带一次性的 `systemCredentials`；其中 `jump` 为可选 JumpServer Host、端口和登录凭据。前端只描述连接参数，不决定平台执行策略。
- 后端根据 `vmId` 查询 VM 清单并解析系统 IP，不接受前端指定系统 IP。
- 后端根据 `diskId + mountPath` 重新验证平台磁盘与系统目录映射，不接受前端指定系统设备、分区和文件系统。
- Provider 只接收 `VmResizeExecutionRequest`；Web 和 API 对外使用 `VmResizeRequest`，防止平台执行字段反向泄漏到前端。
- 所有 Provider 返回统一的 `VmResizeResult`；系统内容量结果使用相同字段和状态语义。

## 原盘扩容

1. 读取平台虚拟磁盘清单。
2. 通过虚拟机操作系统内的 `lsblk`、`df` 读取磁盘、分区、LVM 和真实挂载目录。
3. 按 XenServer 设备号或磁盘容量、顺序映射平台磁盘与系统内磁盘。
4. 过滤 `/boot`、`/boot/efi` 等不允许作为普通数据扩容目标的目录。
5. 执行前验证目标目录、磁盘映射以及 `growpart/parted/sfdisk`、LVM、XFS/ext 工具。
6. Provider 扩大虚拟磁盘；不支持在线扩容时按原策略正常关机并自动启动。
7. 虚拟机操作系统回读新容量后扩展末尾分区；LVM 使用本次增量扩展目标 LV，不占用与本次操作无关的全部 VG 空间。
8. XFS 使用 `xfs_growfs`，ext2/3/4 使用 `resize2fs`，最后回读挂载目录容量。

CentOS 7 兼容顺序为：优先 `growpart`；其次使用支持 `resizepart` 的新版 `parted`；旧版 DOS 分区表使用 `sfdisk -N` 只重写目标末尾分区。`sfdisk` 执行前保存分区表备份，并在命令因内核占用返回非零时回读磁盘表确认是否已经写入。若磁盘表已更新但内核仍是旧容量，VRC 自动正常重启虚拟机操作系统一次，等待 SSH 恢复后继续 `pvresize`、`lvextend` 和文件系统扩展。

平台磁盘已经扩大、虚拟机操作系统尚未生效时，存储探测会根据磁盘末尾空闲、分区与 PV 容量差、VG 空闲容量计算“待分配容量”。用户无需再次增加虚拟磁盘，可直接选择目标目录完成续作。

LVM 设备路径必须使用 `df/findmnt` 返回的稳定挂载源，例如 `/dev/mapper/<vg>-<lv>`。`lsblk` 的 `dm-N` 仅用于识别设备关系，编号会随启动和设备映射变化，也不能作为旧版 `lvextend` 的目标参数。

## 新增磁盘

1. 执行前记录虚拟机操作系统当前磁盘清单并校验目标挂载目录。
2. 下拉候选仅包含 `/data`、`/mnt`、`/srv`、`/opt` 中真实存在、未挂载且为空的顶层目录。
3. 允许输入上述根目录下的新路径；路径不存在时由 VRC 创建。
4. Provider 创建并挂载新虚拟盘。
5. 虚拟机操作系统重新扫描 SCSI 设备，以“新增设备 + 容量匹配”唯一识别本次磁盘，禁止格式化已有文件系统的设备。
6. 新盘创建 GPT 分区和 XFS，使用文件系统 UUID 写入 `/etc/fstab` 后挂载。
7. 写入前备份 `fstab`；挂载失败时恢复备份，并返回部分完成状态。
8. 最终必须回读新挂载目录及容量；低于虚拟磁盘目标容量的安全阈值时判定失败。重启验证时，新目录必须依靠 UUID/`fstab` 自动恢复挂载。

## 新建系统磁盘布局

- CentOS 7 无人值守安装禁止继续使用 Anaconda 默认 `autopart --type=lvm`，该策略会保留未分配空间，导致 120 GiB 虚拟盘仍只有约 42 GiB `/home`。
- Kickstart 显式创建 500 MiB `/boot`、50 GiB 根目录、8 GiB swap，并让 `/home` 使用 `--grow` 接收其余容量；小于标准规格的磁盘会动态缩小根目录，但不低于 20 GiB。
- CentOS 7 安装包列表包含 `cloud-utils-growpart`，后续原盘扩容优先使用成熟的 `growpart`。
- 该策略在安装阶段完成，不依赖安装后的虚拟机操作系统 SSH 登录。后续对已安装系统扩容时，虚拟硬件仍由平台完成，分区/LVM/文件系统生效必须通过操作系统执行通道完成，不得降级为平台单层成功。

## 安全与失败语义

- 系统执行通道由后端策略建立；前端不得选择 SSH、WinRM、Agent 或 Provider 命令。PVE 只有在 QEMU Guest Agent 的 `guest-exec` 命令能力启用时，才能免 VM 密码执行系统扩容；仅能读取 `get-fsinfo` 的监控 Agent 不足以完成分区、LVM 或文件系统变更。`guest-exec` 未启用时，后端返回明确不可用状态，用户可提供 VM SSH 凭据，并在网络隔离时提供 JumpServer。已明确配置 JumpServer 时直接使用跳板，不先等待直连超时。VMware Tools 可提供工具状态和监控数据，但不自动获得 Guest Operations 权限，不能据此跳过系统凭据。
- 后端优先按运行策略和 VM IP 推导执行凭据；默认认证失败时，前端可加密提交系统 Login/Password 和可选 JumpServer 凭据。用户选择“保存到本机”后，整组凭据按连接 ID 和 VM ID 使用 AES-256-GCM 加密写入本机 VRC 数据目录的 `vm-system-credentials.json`，不写入连接配置、扩容记录、活动日志或接口响应。
- 本机凭据文件和临时文件必须被 Git 忽略；仓库只允许保留不含凭据的 `config/vm-system-credentials.example.json` 空示例。保存的凭据认证失效时由后端自动删除，避免持续使用旧密码。
- 凭据文件路径不得依赖仓库目录或硬编码操作系统路径。API 统一通过 `VRC_DATA_DIR` 解析；Electron 打包版由主进程使用平台原生 `app.getPath("userData")/data` 注入绝对路径，并兼容读取旧版用户目录。Windows、macOS 和 Linux 使用各自的平台路径实现。
- 后端无法建立系统执行通道时返回统一的不可用状态，磁盘扩容保持禁用，不向前端暴露 SSH 或 Provider 内部错误结构。
- 所有会修改平台或虚拟机操作系统的动作之前必须完成只读预检。
- 平台变更失败：整体失败，不执行虚拟机操作系统命令。
- 平台成功、操作系统生效失败：返回“虚拟硬件已扩容，但系统内容量自动生效失败”，前端按部分完成展示并刷新平台容量，禁止假报整体成功。
- 系统执行通道不可用：CPU/内存操作仍可执行，磁盘扩容按钮保持禁用，直到后端预检返回可用目录。
- 弹窗磁盘清单和系统目录探测复用后端短缓存及进行中的同一查询；目录探测优先使用刚加载的 VM 行作为只读提示，避免 PVE、XenServer、VMware 重复登录和重复全量 VM 扫描。真正提交扩容时仍由后端重新核对实时 VM 状态。
- 虚拟机已关机：前端直接禁用“资源扩容”入口，后端在 Provider 变更前统一拒绝 CPU、内存和磁盘扩容请求，并在目录探测接口返回 `GUEST_OFFLINE`；不尝试 SSH 握手。平台磁盘理论上支持离线调整，但本入口以现有目录最终生效为完成口径，必须先开机完成目录探测，不能在未知目录映射时合并为一次成功。
- 操作系统工具、磁盘映射或目录预检失败：不得执行平台磁盘变更，不允许降级为虚拟硬件单层成功。
- 磁盘只允许增大，不支持缩小。
- 新盘格式化前必须同时满足：本次新增、容量匹配、无文件系统、未挂载。

## 本机配置路径与读写

- API 统一使用 `VRC_DATA_DIR` 作为本机运行数据根目录；业务配置未单独指定路径时，`ip-pools.json`、`runtime-policy.json`、`preferences.json`、`provisioning.json`、`vm-system-credentials.json` 和 `key.bin` 均从该目录解析，不依赖仓库工作目录。连接仓库、任务状态、定时任务、IP 租约、ISO 缓存和生成文件也统一从该根目录派生。
- `ip-pools.json` 可用 `VRC_IP_POOLS_FILE` 覆盖，`runtime-policy.json` 可用 `VRC_RUNTIME_POLICY_FILE` 覆盖。业务专用文件变量优先于 `VRC_DATA_DIR`，相对路径统一转换为绝对路径。
- Electron 打包版由主进程读取平台原生 `app.getPath("userData")/data`，再以绝对 `VRC_DATA_DIR` 启动内置 API。已有 `~/.virtual-resource-console` 数据且新目录尚未创建时兼容旧目录；Windows、macOS、Linux 不在 API 业务代码中写死路径。
- `appPaths` 是所有本机运行文件的路径入口；后端公共模块 `localConfigFile` 只负责 JSON 配置的路径解析、读取、目录创建、权限和临时文件替换写入。IP 池、运行策略、界面偏好、创建预设、系统凭据等业务模块各自负责字段校验、默认值、错误语义和加密，避免提供可读写任意本机文件的通用 HTTP 接口。
- 真实 `ip-pools.json`、`runtime-policy.json`、`vm-system-credentials.json`、密钥和临时文件必须由 Git 忽略；仓库仅保留脱敏示例或空结构示例。系统凭据正文在写入前使用本机密钥执行 AES-256-GCM 加密。

## 当前验证

- 单元测试覆盖 CentOS 7 LVM 清单解析、稳定逻辑卷路径、XenServer 磁盘映射、原盘扩容命令和新盘格式化挂载命令。
- XenServer `129.21_test2` 原盘续作实测通过：平台磁盘保持 120 GiB，自动扩大 `/dev/xvda2`，重启后执行 PV/LV/XFS 扩展，`/home` 从约 42 GiB 增至约 62 GiB。
- XenServer `129.21_test2` 新盘实测通过：在线新增 20 GiB `/dev/xvdb`，创建 GPT/XFS，使用 UUID 写入 `fstab` 并挂载 `/data`；正常重启后 `/home` 和 `/data` 均自动恢复，容量回读一致。
- VMware 只读实机验证通过：平台 VMDK 可与虚拟机操作系统内的 `/dev/sda`、LVM、`/`、`/home` 正确关联。未选择业务测试 VM 执行真实扩盘。
- PVE 平台磁盘解析和 API 命令由自动测试覆盖；当前可见 VM 的系统账号不符合默认口令规则，尚未对真实 VM 执行变更验证。
